# GraphiQ QA audit and repair plan — 9 October 2026

## Outcome and scope

Both supplied hospital activity documents now compile and render every declared flow, and retain their structure after printing and re-importing. The downloadable guide describes the implemented syntax. Errors use concise language and source locations that open the editor and select the affected code.

This audit covered the supplied screenshots and code, the downloaded guide, all 14 diagram examples, parser/compiler/printer behavior, editor diagnostics, asynchronous layout, diagram creation, persistence, imports, exports, and the repository's browser regression suite. Evidence is local source inspection and automated tests in Chrome, with a 390 × 844 viewport check and visual inspection of its screenshot. It is not a claim that every possible UML document or every browser has been exhaustively tested.

## Execution plan and validation

1. Establish baseline: existing 298 unit tests and 55 Chrome browser tests passed, demonstrating that the reported cases were absent from the suite.
2. Fix activity syntax and semantic identity. Preserve both supplied documents as exact regression fixtures rather than rewriting them to hide unsupported syntax.
3. Improve diagnostics, source maps, editor navigation, and collapsed-panel interaction.
4. Exercise asynchronous edits, palette-to-code round-trips, mobile layout, and import/export behavior. Repair adjacent defects found by those checks.
5. Make guide examples executable regression cases, reduce unnecessary startup loading, and verify production chunks.

## Remaining verification and bounded limitations

- Firefox, Safari/WebKit, real touch devices, and screen-reader behavior were not tested. The narrow viewport is Chrome, not a real-device certification. Extend the browser matrix before claiming cross-browser release readiness.
- The suite emitted intermittent `ResizeObserver loop completed with undelivered notifications` messages during large activity rendering. The tested diagrams rendered correctly; the cause has not been isolated. Investigate with a production trace and manual resize/pan checks before treating it as a functional defect or suppressing it.
- Vite still reports large chunks and a pre-existing persistence import that is both static and dynamic. The main bundle reduction is build evidence, not measured field performance. Further canvas/parser splitting should be driven by a production network and interaction profile.
- A React Flow attribution warning remains from existing canvas configuration. Confirm the project's intended configuration separately; the tests do not establish subscription status.
- UML validation is intentionally limited to implemented rules. Branch warnings identify obvious ambiguities; they do not prove workflow correctness, payment completeness, or full UML conformance.

**Release assessment:** Ready with known limitations for the tested local Chrome workflows. A broader browser or production release requires the additional evidence listed above. No deployment or external publication was performed.

For rollback, revert these source changes as a group. The repair changes no persistence schema and adds no dependencies. Re-run the original smoke, persistence, and export tests after reverting.
